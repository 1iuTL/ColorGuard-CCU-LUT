============================================================
   ColorGuard 使用说明（傻瓜版）
   解决：控制中心切到 sRGB 后 画面变暗 / 出现彩噪
============================================================

【这个程序是干什么的】

如果你的机械革命笔记本，在"机械革命控制中心"里把色域从【原色域】切到【sRGB】之后，
画面明显变暗、渐变和暗部出现彩色噪点或竖条，而切回【原色域】就一切正常 ——
那基本就是这个问题（控制中心新版漏了"刷新屏幕色彩曲线"这一步）。

本程序做的事很简单：每次你切换色域，它替你补上那一步，让两个档位都显示正常。

· 不是驱动、不改系统设置、不联网、不开机自启
· 不需要管理员权限
· 免安装：删掉文件夹就等于彻底卸载（无注册表残留、无服务）


【使用前，先确认两件事】

1）你的电脑里有"机械革命控制中心"（开始菜单能搜到）。
2）Windows 的"自动管理应用的颜色"是开着的：
     设置 → 系统 → 显示 → 颜色管理 → 打开【自动管理应用的颜色】
   （找不到这一项说明系统较旧；那样的话本程序对 sRGB 档帮助有限。）


【第一步：解压】

把 ColorGuard-CCU-LUT.zip 解压到一个固定目录，例如：
      D:\软件\ColorGuard

建议不要放在桌面或 C 盘根目录（容易误删）。
解压后能看到这些：
      ColorGuard.exe     ← 双击运行的就是它
      使用说明.txt       ← 就是本文
      README.md  src\  docs\

如果双击没反应，或提示"此文件来自其他计算机，可能被阻止"：
      右键 ColorGuard.exe → 属性 → 右下角勾【解除锁定】→ 确定
（从微信/QQ 传过来的文件，经常需要这一步。）


【第二步：运行】

双击 ColorGuard.exe。

· 如果弹出"Windows 已保护你的电脑"：
      点【更多信息】→【仍要运行】
  说明：程序是用源码现场编译的，没有购买代码签名证书，所以会显示"未知发布者"。
        源码就在 src\ColorGuard.cs（纯文本，10 KB），可以自己看，也可以用
        build.cmd 重新编译一个。

· 打开后是一个小窗口，写着"守护状态：已停止" —— 这是正常的，此刻还没开始工作。


【第三步：先"捕获"你自己的屏幕曲线（只做一次）】

这是最关键的一步，别跳。

1. 打开"机械革命控制中心"，把色域切到【原色域】。
   看一眼屏幕，确认颜色正常（不偏色、不发灰）。
2. 回到 ColorGuard 窗口，点【捕获当前曲线】。
   提示"已捕获原色域曲线"，目录里会多出 profile-default.ramp。
3. 在控制中心把色域切到【sRGB】，同样确认画面正常。
4. 再点一次【捕获当前曲线】。
   提示"已捕获sRGB曲线"，目录里会多出 profile-srgb.ramp。

（如果你平时根本不用 sRGB 档，第 3、4 步可以跳过。）

注意：捕获的是"此刻屏幕实际在用的曲线"，所以一定要在画面正常时点。


【第四步：开启守护】

点【开启守护】。状态变成绿色"运行中"，就完成了。

以后你每次在控制中心切换色域，它都会自动把屏幕曲线改成对应的正确值
（实测几十毫秒内完成，你不用做任何操作）。


【日常使用】

· 想关掉：点【关闭守护】，或直接关窗口。
· 本程序不会开机自启。电脑重启后，需要再双击打开一次、点【开启守护】。
· 想省事：右键 ColorGuard.exe → 发送到 → 桌面快捷方式。
· 出问题时：点【打开日志】看记录（每一条都有时间），可以把 ColorGuard.log 发给开发者。


【常见问题】

问：点了开启守护，画面没变化？
答：看窗口里三行字：
     "守护状态"=运行中、"控制中心当前档案"=你刚切的档位、
     "曲线来源"=已捕获（如果显示"未捕获(恒等)"，说明第三步没做）。

问：切色域的一瞬间还是会闪一下（彩线/偏暖）？
答：正常现象。控制中心和 Windows 是分几步切换的，中间约 0.1~0.3 秒两边不同步。
    本程序只保证"切完之后"是对的。想完全看不到闪，就固定用一个色域档、别来回切。

问：原色域看起来偏亮 / 偏淡？
答：说明原色域那条曲线没捕获（现在用的是"恒等"直通）。做一遍第三步。

问：sRGB 看起来太艳（不像 sRGB）？
答：检查 Windows 的"自动管理应用的颜色"是否被关掉了。sRGB 这一档需要系统来做
    色域变换，关掉的话本程序只能把屏幕曲线设成直通，颜色就会过饱和。

问：提示"无法访问"或"权限不足"？
答：本程序不需要管理员权限，直接双击运行即可，不要用"以管理员身份运行"。

问：点【捕获当前曲线】没反应？
答：确认控制中心当前档位是【原色域】或【sRGB】之一（其它档位程序不认识）。

问：我电脑不是机械革命，能用吗？
答：只要是同类"控制中心"（AiStone 那套，注册表有 OEM\\GamingCenter2）可以试；
    联想/华硕/戴尔/惠普等其它品牌打开后什么都不会做（不会坏，也没效果）。

问：想卸载？
答：关掉程序，删掉整个 ColorGuard 文件夹。无注册表残留、无自启项、无系统服务；
    屏幕色彩会在下次系统或控制中心写入时恢复默认。


【技术信息（看不懂可以跳过）】

· 原理：监听注册表 HKLM\SOFTWARE\OEM\GamingCenter2 的变化，在色域切换后调用
        SetDeviceGammaRamp 写入正确的显示器伽马曲线（sRGB→恒等，原色域→捕获值）。
· 行为：不联网、不写注册表、不装服务、不自启、单实例。
· 开源（MIT 许可）：https://github.com/1iuTL/ColorGuard-CCU-LUT
· 版本 1.0.0 · 2026-10

============================================================
  【防呆设计】（2026-10-18 新增，v1.1）
============================================================

为什么加：10-18 出现过一次"误捕获"——在 sRGB 档下、画面还是暗的（原色域曲线）时
点了【捕获当前曲线】，于是把"暗曲线"存成了 sRGB 的正确曲线，守护从此判定"已正确"、
不再纠正，画面就一直暗/彩噪。

现在有三道防线：

1) 捕获时拒绝"张冠李戴"
   · 当前是 sRGB 档，但屏幕还在用【原色域】曲线 → 直接拒绝，提示等画面刷新
   · 当前是【原色域】档，但屏幕还在用【sRGB】曲线 → 直接拒绝

2) sRGB 档捕获"非恒等曲线"要二次确认
   · 正常 sRGB 档应由系统按 ICC 校正，屏幕 LUT 保持【恒等】
   · 若捕获到的曲线偏离恒等 → 弹窗警告，只有你确认画面正常才保存

3) 启动时自检（自动修复）
   · 若 profile-srgb.ramp 与 profile-default.ramp 完全重合（误捕获的典型特征）
   · 程序自动把 sRGB 曲线恢复为【恒等】，旧文件备份为
     profile-srgb.ramp.bak-日期-时间，并在日志里记一条 self-check

另外：每次【捕获】前都会自动备份旧文件（.bak-时间），日志里记录前后总和，
误操作永远可回溯。
